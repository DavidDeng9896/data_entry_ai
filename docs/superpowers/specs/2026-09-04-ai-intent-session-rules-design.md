# AI 意图路由 + 会话规则（取代关键词硬判）

日期：2026-09-04  
分支：`cursor/ai-intent-session-rules-03dc`  
状态：书面 spec 待用户确认后再写实现计划

## 1. 问题

当前导入对话用关键词硬路由（`为啥` → 只问答、`识别` → 才抽数）。结果表为空、用户已上传附件并说「希望快速分析」时，会被判成问答：故意不读附件，回「没收到附件 / 告诉我化合物号」，体验很差。

客户提示词也无法稳定变成「本轮导入约束」：要么被问答模式丢掉，要么只能靠少数识别关键词触发整次重抽。

## 2. 已确认需求

| 项 | 结论 |
| --- | --- |
| 意图谁判 | **AI 判定**，不用关键词硬路由主导 |
| 会话规则 | **本轮生效 + 当前导入会话静默积累**；关对话框丢弃；**不自动写 Skill** |
| 抽数时旧行 | **整表重抽覆盖**当前预览表 |
| 拿不准 | **聊天里自然语言确认**，不静默替用户做死决定；不要确认按钮面板 |
| 会话规则 UI | **静默**，不单独做规则面板 |
| 本地改格子 | 仅很确定时走本地 `edit`；稍有歧义 → `clarify` |
| 方案 | **轻量意图模型先判，再执行**（方案 1） |

## 3. 设计块 1：意图路由

每轮用户发送后，先做一次短判定。输入上下文尽量小：

- 用户本句
- 是否有可用附件、附件文件名列表（不塞全文）
- 结果表是否已有预览行（行数 + 少量 `cpds_id` 样例即可）
- 当前会话规则摘要

模型只返回结构化结果：

| 字段 | 含义 |
| --- | --- |
| `action` | `extract` / `answer` / `edit` / `clarify` |
| `rule_delta` | 本句要并入会话的规则文本（可空） |
| `reason` | 一句话供日志/调试，不直接怼用户 |

执行约定：

- **`extract`**：合并 `rule_delta` → 读附件 → 按会话规则抽数 → 预览表整表覆盖
- **`answer`**：合并 `rule_delta`（若有）→ 用已填表 + 对话回答；**默认不重读附件**
- **`edit`**：仅当非常确定「只改已填格子、不重抽」→ 本地改格子
- **`clarify`**：合并明确的 `rule_delta`；聊天自然语言问清（只答 / 只改 / 按新规则重抽）；等用户下一句再判

删除（或降为仅兜底、不主导）：`CHAT_PHRASES` / `RECOGNIZE_PHRASES` 硬路由。

## 4. 设计块 2：会话规则

- **存放**：当前导入对话框会话（前端状态随请求带回；关对话框 / 新开导入清空）。
- **写入**：每轮 `rule_delta` 追加合并；同义可折叠；不弹规则面板；不默认落 Skill。
- **使用**：`extract` / `edit` 时把「当前会话规则」放入模型上下文（在 Skill 之上作为本轮约束）；`answer` 也可带上，便于解释「按你刚才说的…」。
- **空 delta**：不改会话规则。
- **清空/撤销**：用户说「忘掉刚才的规则 / 按默认来」时，判定给出清空或删条，静默生效；回复可用一句话确认。

## 5. 设计块 3：附件、覆盖与确认流

### 5.1 读附件

- `extract`：读底部已上传、未失败的附件（多文件；坏文件跳过并点名，沿用现有能力）。
- `answer` / `edit` / `clarify`：默认不解析附件。
- 表空 + 有附件 + 用户要分析/抽数：判定应倾向 `extract`，禁止回「没收到附件」。
- **空发送 + 有附件**：直接 `extract`（可跳过短判定，或钉死为 extract）。

### 5.2 覆盖

- `extract` 成功后：当前预览表整表替换为本次抽出行。
- 已「确认导入」落库的历史不受影响。

### 5.3 clarify

- 自然语言问清即可；用户下一句再走同一套判定。
- 不做按钮式确认条。

### 5.4 失败

- 判定失败：降级「有附件则 extract，否则 answer」；步骤里说明「意图判定失败，已按默认处理」。
- 抽数失败：保留旧预览表，不空盖；错误照常展示。

## 6. 非目标（本次不做）

- 不把会话规则自动合并进 Skill / 结果表永久配置（可后续加「保存为 Skill」）。
- 不做会话规则侧栏、不做确认按钮组。
- 不改为按化合物合并覆盖（本次明确整表覆盖）。
- 不在本次解决模型本身变慢/并行限流问题。

## 7. 验收场景

1. 上传 PDF，说「希望快速分析，不要反复思考」→ `extract`，开始读附件；会话记入「快速、少反复思考」类约束；不追问化合物号。
2. 表已有行，问「为啥 HW1 没有？」→ `answer`，不重抽、不覆盖。
3. 表已有行，说「过滤掉对照再导」→ `extract`（或先 `clarify` 若模型不稳），成功后整表覆盖；会话记入过滤规则。
4. 「小数超过 2 位改成 2 位」且表有行 → 倾向 `edit` 本地改；若模型拿不准 → `clarify`。
5. 空发送 + 有附件 → 直接抽数。
6. 关导入对话框再开 → 会话规则清空。

- 抽数路径：system/user 中注入会话规则；成功则覆盖预览 rows。
- 单测：上述验收场景的判定与 stream 行为（mock 判定亦可）。
