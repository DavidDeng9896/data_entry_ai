# 分章意图 + 结果区读图

日期：2026-09-05  
分支：`cursor/section-first-parse-03dc`  
状态：方案 1 已确认，按此实现

## 1. 问题

裁页把文件名和 sheet 混在一起匹配，会丢掉正文。更根本的是：没有「先看大章节、再判断结果在哪」的统一流程；Word 不能解析；嵌入图不读；找不到时不会列出章节请用户指认。

## 2. 已确认需求

| 项 | 结论 |
| --- | --- |
| 顺序 | 先切大章节，再决定读哪几块 |
| 无 Skill 指导 | 标题启发式；拿不准再模型判章节（选项 B） |
| 对不上 | 全文再抽；仍空则列出章节 + 一句猜测，请用户指认（选项 C） |
| 图 | 只读被标成结果区的章节里的图（选项 C） |
| 第一期格式 | Excel + PDF + Word 同一套（选项 C） |
| 架构 | 统一章节树，再 keep / 全文 / 问人 |

## 3. 章节树

每种格式先切成：

```
{ title, kind: sheet|page|heading|file, text, images[] }
```

- Excel：每个 sheet 一章；该 sheet 关联的嵌入图挂到该章。
- PDF：有书签按书签，否则按页；页内图挂到该页。
- Word：按 Heading 1/2 切；段内图挂到当前标题章。
- 包装行 `### 文件:` 只做前缀，不参与选章。

## 4. 选章

1. 有 Skill「读取范围」→ 按指名页（只对真正页名，不对文件名）。
2. 否则标题启发式：结果 / 过程 / 不明。
3. 不明章短调模型（有 key 且非 mock）。
4. 有结果区 → 只送这些区的文字；区内可解码的图送视觉（或把图意写入正文）。
5. 无结果区 → 送全文文字再抽。
6. 仍抽不出行 → 回复章节目录 + 猜测，请用户回「看 Result sheet / 看第 3 页」。
7. 用户点名后只读点名的章（含图）。

## 5. 图

- 结果区内：png/jpg/webp 直接送视觉；emf/ole 能转则转，转不出在该章注明「有图未能解码」。
- 过程区的图不读。
- 单独上传的图片文件仍走现有视觉识别。

## 6. 非目标

- 不自动把指认结果写进 Skill。
- 不一次把全部嵌入图送视觉。
- 不做确认按钮条（自然语言点名即可）。
