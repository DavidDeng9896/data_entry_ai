# AI 建表：从文件/对话生成结果表列配置

日期：2026-09-02  
分支：`result_table_setting`  
状态：书面 spec 待用户确认后再写实现计划

## 1. 问题

当前必须先手动「新建结果表」（表名 + 逐列 `field` / `title` / `type` / `required` / `options` / `description`），才能走「AI 导入」填数据。用户拿到的是 CRO 报告或口述指标，不想自己分析该建哪些内部列。

本功能在**现有「新建结果表」弹窗**里加与导入一致的 AI 侧栏：用户上传结果文件和/或多轮问答后，AI 按内部规范抽出列配置和一份可编辑的 Skill 草稿；用户确认后点「创建」建表，并可选保存 Skill。

## 2. 已确认需求

| 项 | 结论 |
| --- | --- |
| 抽列策略 | 按内部规范「翻译」，不是照抄源表头（如 `Half-life (h)` → `t1_2_hr` + 显示名 + `number` + 列说明） |
| 入口 | 仍点「新建结果表」；弹窗内展开 AI 侧栏（与导入同一套交互） |
| 确认 | AI 只填草稿；用户点现有「创建」才落库。AI 预填表名、描述 |
| 输入 | 文件与文字可混用；可先上传再口头改列 |
| 编辑 | 左侧可手改；也可继续对话让 AI 改；两者都要 |
| Skill | 同时生成 Skill Markdown 草稿，用户可当场改；创建时另存且**不启用** |
| 文件 | 与导入相同：xlsx/xls/csv/tsv/pdf/png/jpg/txt/md，可多文件 |
| 多 sheet | 结果页、方法页尽量都看，用于判断主源和「不建哪些列」 |
| 列很多时 | 只抽真正像结果的列，不把过程/方法表抄成表头 |
| 范围外 | 不在本次用同一文件接着填数据；不给已有表改表头 |

## 3. 交互

### 3.1 布局

中间仍是现有建表表单。标题栏增加「AI 助手」（对齐导入的「AI识别导入」）。

点开后，在弹窗**右侧展开对话栏**，交互与 `ImportDialog` 侧栏一致：

- 上传、多文件、多轮、流式进度、可收起（后台继续）
- 收起后出现侧边把手
- 标题为「建表助手」
- **不放**「自动匹配 Skill」下拉（本流程是生成新 Skill，不是选用已有模板）

左侧表单增加页签：

- **列配置**（默认）：现有列编辑表；AI 回写后停在此页
- **Skill 草稿**：Skill 名称 + Markdown 编辑框（与设置里 Skill 编辑器同类）；Skill 被 AI 更新时页签给「已更新」提示

页脚不变：校验错误 +「取消 / 创建」。

首页不另加独立「AI 建表」按钮。

### 3.2 流程

1. 打开「新建结果表」（空表名 + 一列占位）。
2. 展开侧栏，上传文件和/或输入需求（例如「按内部字段建 Dog PK，只要 CL / Vss / AUC / T1/2 / %F」）。
3. 后端解析全部附件的全部 sheet，模型只抽结果列，写出表名、描述、列、Skill。
4. `schema` 轮按 §4.3 回写（列和 Skill 整份替换；表名/描述仅在草稿为空或用户要求改时写入）；用户可手改或继续问。
5. 点「创建」：建表；Skill 非空则再存一条 Skill，默认不启用。回到列表。

关闭弹窗且未点「创建」：不建表、不存 Skill。助手仍在跑时，收起行为与导入一致（可后台继续）；关闭未创建的草稿直接丢弃。

## 4. 后端

### 4.1 复用与隔离

- **复用**：`POST /api/recognize/upload`、`file_parser`（全 sheet）、SSE 事件形态（`step` / `done` / `error`）、现有 `POST /api/tables` 与 `POST /api/skills`。
- **隔离**：不改导入填表提示词，不把「设计列」塞进 `/api/recognize/chat`。导入契约仍是「不许扩列、只填已有字段」。

### 4.2 新接口

- `POST /api/tables/schema/chat`
- `POST /api/tables/schema/chat/stream`

请求：

```json
{
  "messages": [{"role": "user|assistant", "content": "..."}],
  "file_ids": ["..."],
  "name": "",
  "description": "",
  "columns": [],
  "skill_name": "",
  "skill_md": ""
}
```

当前草稿一并上传，便于用户手改后再让 AI 改一版。

响应：

```json
{
  "reply": "短中文说明",
  "intent": "schema|chat",
  "name": "Dog PK",
  "description": "...",
  "columns": [
    {
      "field": "cpds_id",
      "title": "Cpds ID",
      "type": "text",
      "required": true,
      "options": [],
      "description": "化合物内部编号"
    }
  ],
  "skill_name": "PK · … 版式",
  "skill_md": "# …\n"
}
```

仅当 `intent === "schema"` 且存在有效列时，前端才回写表单。`chat` 轮只展示 `reply`。

### 4.3 意图

| 本轮 | 意图 | 是否改表单 |
| --- | --- | --- |
| 有新附件，或用户要求抽列/改列/改表名（「抽出列」「改成 number」「去掉 CLint」「表名改成…」） | `schema` | 是，见下方回写 |
| 「为什么抽这列」「这是什么意思」等问答 | `chat` | 否 |

`schema` 回写（与导入覆盖行一样，列不做字段级 merge）：

- **列、Skill 名称、Skill 正文**：整份替换。
- **表名、描述**：当前草稿为空时用模型结果；草稿已有内容则保留，除非用户本轮明确要求改名/改描述。

手改的列会保留到下一轮 `schema` 之前（下一轮 `schema` 仍整表替换列）。

### 4.4 校验与失败

- `field` 去重、非空；`type` 只允许 `text|number|date|select`，非法则收成 `text`。
- 解析失败、模型失败、有效列数为 0：只回复原因，**不清空**已有草稿。
- 「创建」：表名为空或无有效列 → 与现网一致，拦在弹窗，不建表、不存 Skill。
- 建表成功、存 Skill 失败：表保留，提示 Skill 未保存，可到设置里补。不回滚表。
- Mock：无真实模型时返回固定演示列 + Skill，仅用于无 key 时把 UI 点通。

### 4.5 创建落库

1. `POST /api/tables`（现有）。
2. `skill_md` 去空白后非空 → `POST /api/skills`（`name` + `content`），**不调用 enable**。
3. 成功后关弹窗，刷新列表。

## 5. AI 抽列与 Skill 正文

单独系统提示词（建表基线），不复用导入基线。

### 5.1 看文件

- 全部 sheet/章节都送入（封面、汇总、方法、原始数据），用来认实验类型、主源、不该建的列。
- 只为「真正像结果」的列建字段：实体 ID、会成为结果维度的种属/条件、已算好的终点（CL、T1/2、AUC、%F、IC50、%Fu、Remaining% 等）。
- 默认不建列：试剂/货号、SOP、原始时程、峰面积、标曲、对照专用列、方法参数、签字日期。这些写入 Skill 的「不映射 / 跳过」。
- 40+ 源列时按上面收，宁可少，不把过程表抄成结果表。

### 5.2 内部列规范

| 属性 | 规则 |
| --- | --- |
| `field` | 英文 snake_case，带单位/条件，如 `iv_1mpk_cl_l_h_kg`；表内唯一 |
| `title` | 显示名，可中英 |
| `type` | 数值终点 `number`；ID/名称 `text`；日期 `date`；封闭枚举 `select` + `options` |
| `required` | 通常仅实体键（如 `cpds_id`） |
| `description` | 一两句：含义、单位、常见源表头 |

无文件纯聊天：按用户提到的指标出同样结构；缺单位在 `description` 写「单位待确认」，不编造未提到的列。

表名优先用内部实验类型（`Dog PK`、`MMS`、`PPB %Fu`），不用原始文件名。描述一句话说清记什么。回写时遵守 §4.3：草稿里已有表名/描述则不覆盖，除非用户本轮明确要改。

### 5.3 Skill 草稿格式

对齐现有 `doc/skills/*.md`，章节固定：

```markdown
# {实验类型} · {版式/供应商}

## 匹配线索
## 目标结果表
## 读取范围
## 主源
## 实体与过滤
## 字段映射
## 不映射
## 特殊值
```

- 「目标结果表」= 当前建议表名。
- 「字段映射」目标 `field` 必须与左侧列一致。
- 「读取范围 / 不映射」写清看过但不当结果列的页。
- 无文件时：匹配线索写「用户描述」；不确定则不编造具体 sheet 名。

### 5.4 模型输出契约

对话回复用短中文：抽了哪些列、丢掉了什么。结构化结果用约定块（对齐导入的 `<<<ROWS>>>`）：

```
<<<SCHEMA>>>
{ "name", "description", "columns", "skill_name", "skill_md" }
<<<END>>>
```

前端只在本轮 `intent === "schema"` 时解析，并按 §4.3 回写（不是无条件覆盖表名）。

## 7. 测试

### 7.1 自动化（可 Mock）

覆盖回写与落库，不依赖外网：

1. 纯聊天出列：指标列表 → 表名、内部 `field`、合理 type、Skill 草稿。
2. 多 sheet 文件：只出现结果列；Skill 含读取范围与不映射。
3. 追问改结构：`schema` 整表替换；纯问答不改表单。
4. 请求带上当前草稿；创建：无 Skill 只建表，有 Skill 多一条未启用记录；表名为空不建。
5. 0 列 / 接口失败：草稿不被清空。

### 7.2 真实 API 验收（必须）

实现完成后的手工/集成验收**关闭 Mock，使用真实文本模型**（设置里已配的 `text_model`，或环境中的真实 key）。至少跑通：

1. 上传一份真实多 sheet 报告（含结果页 + 方法/原始页）→ 列是内部字段、方法页未进表头、Skill 可编辑。
2. 不传文件，只口述一组指标 → 出列 + Skill。
3. 追问改一列 / 改表名 → 草稿更新。
4. 点「创建」→ 列表出现新表，设置里出现未启用 Skill。

Mock 仅保留给无 key 的 UI 冒烟，**不能代替**上述真实 API 验收。

## 8. 非目标（本迭代不做）

- 创建后自动打开「AI 导入」并用同一文件填行
- 已有表的「表头」设置里复用本助手
- 创建时自动启用新 Skill
- 首页单独「AI 建表」入口
- 改导入识别提示词或 `/api/recognize/chat` 语义

## 9. 风险

- 模型把方法表头建成结果列：靠提示词 + 验收样例约束；用户可手删或追问去掉。
- 弹窗加侧栏后偏挤：宽度/收起行为对齐导入，不另造布局。
- 建表与存 Skill 非原子：接受「表在、Skill 失败可补」，不回滚。
