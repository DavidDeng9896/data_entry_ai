## 1. 产品概述

### 1.1 产品名称

**数据录入 Agent**（Data Entry Agent）

### 1.2 一句话定义

面向药物研发场景的智能数据导入工具：用户先定义「结果表」结构，再上传 CRO 报告、仪器导出等非标准文件，由 AI 自动识别并填入表格，经人工核对确认后完成导入。

### 1.3 产品定位

本产品当前是一个**可独立运行的导入工作台原型**，聚焦「**非标准实验报告 → 结构化结果表**」这一核心链路。它在交互上模拟了未来「库配导入」产品中的识别与确认环节，但**尚未对接化合物库、样本注册、ObservationIngress 等下游系统**。

从更长远的规划看（参见 `doc/AI_data_import/data-import-agent-spec.md`），本产品能力将演进为与化合物库同售的「库配导入」功能：文件解析 → 模板匹配 → 人工确认 → 写入库内观测数据。当前版本是该愿景的**前端交互 + AI 识别引擎**竖切实现。

### 1.4 适用实验类型（示例）

系统通过「结果表 + Skill 模板」组合适配不同 assay，已预置或验证过的类型包括：

| 类别 | 示例 |
| --- | --- |
| ADME | 微粒体稳定性（MMS）、蛋白结合率（PPB）、CYP 抑制、热力学溶解度 |
| 体内 PK | 小鼠/大鼠/犬 PK（WinNonlin 参数表） |
| 体外活性 | HCT116 细胞增殖、生化酶活（ADP-Glo IC50）、hERG |
| 其他 | 结合实验（Binding Assay）等自定义表 |

用户也可自行新建任意结果表，不限于上述类型。

## 2. 目标用户与典型场景

### 2.1 目标用户

| 角色 | 如何使用 |
| --- | --- |
| **实验数据录入员** | 将 CRO 返回的 Excel/PDF 报告批量转为结构化表格 |
| **项目负责人 / 数据管理员** | 维护结果表结构、Skill 模板，规范团队导入口径 |
| **研发 IT / 实施人员** | 配置模型 API、导入 Skill、对接后续库系统 |

### 2.2 典型使用场景

**场景 A：历史 CRO 报告补录**

研究员收到一份 3D BioOptima 的微粒体稳定性报告（xlsx），需要把各化合物的 T1/2、30 min 剩余量填入内部结果表。启用对应 MMS Skill 后上传文件，AI 识别出 6 行数据，核对无误后确认导入。

**场景 B：同类型实验的重复导入**

团队已配置好「Dog PK」结果表和普瑞昇 PK Skill。第二份结构相同的报告上传后，AI 按相同规则快速映射，用户只需微调个别单元格。

**场景 C：版式不确定时的交互式导入**

用户上传一份从未见过的报告，不选 Skill，在 AI 助手对话中补充规则（如「IC50 取 A 列，单位 nM」「对照化合物不要导入」），然后重新识别。

**场景 D：从 Excel 手工粘贴 + AI 混合**

用户从报告里复制部分数据粘贴到表格，其余列让 AI 从附件中补全。

## 3. 核心价值

| 价值点 | 说明 |
| --- | --- |
| **降低手工誊录成本** | 将「打开报告 → 找表 → 逐格复制」变为「上传 → AI 填表 → 核对」 |
| **结构化的导入口径** | 结果表定义了唯一允许的字段清单，AI 不会随意发明列名 |
| **可复用的领域规则** | Skill 模板把 CRO 版式、列映射、过滤规则沉淀下来，同类报告越用越快 |
| **人机协同，不盲信 AI** | 所有数据先进入可编辑表格，经校验与用户确认后才算导入成功 |
| **保守识别策略** | 基线提示词要求「不编造、不扩列、不确定留空」，减少静默错误 |
| **零配置可演示** | Mock 模式无需 API Key 即可体验完整交互流程 |

## 4. 系统架构

### 4.1 技术栈

| 层级 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 + Vite + VXE Table | 单页应用，表格编辑与 AI 助手侧栏 |
| 后端 | FastAPI + Python 3.10+ | REST API，文件解析与 AI 调用 |
| 数据库 | SQLite | 结果表、列配置、Skill、模型设置 |
| AI | OpenAI 兼容 API | 文本模型（Excel/PDF/CSV）+ 视觉模型（图片） |
| 文件解析 | pandas、openpyxl、pdfplumber | 将源文件转为 Markdown 表格文本供 LLM 阅读 |

### 4.3 三层 AI 规则体系

识别质量由三层规则叠加决定，优先级从高到低：

1. **目标结果表列定义** — 决定能写哪些字段、类型约束（硬边界）
2. **Skill 模板** — 决定具体 CRO 版式怎么读、怎么映射（软规则，可覆盖基线偏好）
3. **基线系统提示词** — 教模型如何勘查文件、保守映射、何时留空（通用方法论）

用户在对话中补充的规则，在多轮识别模式下作为第四层弱信号参与。

## 5. 功能模块详解

### 5.1 结果表管理

结果表是本产品的核心配置单元，代表一种实验类型的「目标数据结构」。

**已实现能力：**

| 功能 | 说明 |
| --- | --- |
| 新建结果表 | 一步完成表名、描述、全部列配置 |
| 列表展示 | 卡片式展示所有结果表，显示列数 |
| 重命名 / 改描述 | 就地修改表元信息 |
| 复制建新表 | 复制已有表的列配置，快速创建变体（如 Dog PK → Monkey PK） |
| 删除 | 删除表及其全部列配置 |
| 从现有表复制列 | 新建时可一键复制其他表的列结构 |

**列配置项：**

| 属性 | 说明 |
| --- | --- |
| `field` | 字段标识（英文，程序用） |
| `title` | 列显示名称 |
| `type` | 类型：`text` / `number` / `date` / `select` |
| `required` | 是否必填 |
| `options` | 下拉类型的候选值列表 |
| `description` | 列说明，供 AI 理解语义（如「单位 nM」「化合物内部编号」） |

### 5.2 表头设置

每张结果表可独立维护表头，与导入流程解耦。

- 支持增删列、修改类型与必填标记
- 保存时校验字段名唯一、非空
- 表头变更后，再次打开导入弹窗会自动加载最新列定义

### 5.3 导入工作台（核心）

点击结果表卡片上的「AI 导入」进入全屏导入弹窗，包含**左侧数据表格**和**右侧 AI 助手**两部分。

#### 5.3.1 表格编辑能力

| 能力 | 说明 |
| --- | --- |
| 单元格编辑 | 单击选中后可直接键入；双击进入编辑态 |
| 键盘导航 | 支持方向键、Tab、Enter 在单元格间移动 |
| Excel 粘贴 | 从 Excel 复制区域后粘贴到表格，自动按行列展开 |
| 复制 / 剪切 | 选中单元格后 Ctrl+C / Ctrl+X |
| 行操作 | 添加行、下方插入、删除行 |
| 右键菜单 | 下方插入行、删除行、清空单元格 |
| 下拉列 | `select` 类型列显示下拉选择器 |
| 列宽调整 | 可拖拽调整列宽 |
| 首列固定 | 序号列与第一数据列左固定，方便宽表浏览 |

#### 5.3.2 数据校验

| 规则 | 行为 |
| --- | --- |
| 必填校验 | 已填写行中，必填列为空则标红 |
| 数字校验 | `number` 类型列接受空值、纯数字、科学计数法、NA/N/A 等常见占位符 |
| 下拉校验 | `select` 类型列的值须在候选列表内 |
| 空行跳过 | 完全空白的行不参与校验 |
| 确认导入拦截 | 存在校验错误时禁止确认；无有效数据行时提示警告 |

#### 5.3.3 AI 识别导入

| 能力 | 说明 |
| --- | --- |
| 一次性识别 | 上传文件后直接映射到目标列（`/api/recognize/run`） |
| 多轮对话识别 | 在助手侧栏通过对话补充规则、反复识别（`/api/recognize/chat`） |
| 多文件上传 | 一次可上传多个附件，合并解析后识别 |
| Skill 选择 | 导入时可选择 Skill 模板，AI 优先遵循其映射规则 |
| 默认 Skill | 系统自动选中「已启用」的 Skill |
| 识别结果覆盖 | AI 返回的行数据会覆盖当前表格内容 |
| 识别状态提示 | 顶部通知栏显示识别结果行数、错误信息 |

#### 5.3.4 AI 助手侧栏（对话式导入）

| 能力 | 说明 |
| --- | --- |
| 展开 / 收起 | 可收起侧栏，识别在后台继续 |
| 附件上传 | 支持 xlsx、xls、csv、tsv、pdf、png、jpg、txt、md |
| 消息排队 | 识别进行中时，新消息自动排队 |
| 立即重导 | 识别进行中可打断当前任务，按新指令立即重跑 |
| 执行计时 | 显示识别耗时 |
| 未读提示 | 收起侧栏后，识别完成显示「有新结果」角标 |
| 对话历史 | 完整保留用户与助手的对话记录 |

### 5.4 Skill 模板管理

Skill 是用 Markdown 编写的「导入规则说明书」，描述特定 CRO 版式的主源定位、列映射、过滤名单、单位换算等。

**已实现能力：**

| 功能 | 说明 |
| --- | --- |
| 列表浏览 | 查看所有 Skill 及启用状态 |
| 新建 / 编辑 | 内置 Markdown 编辑器 |
| 启用（单选） | 同时只能启用一个 Skill，作为导入时的默认模板 |
| 导入 .md 文件 | 上传 Markdown 文件自动创建 Skill |
| 导出 .md 文件 | 下载 Skill 内容为 Markdown 文件 |
| 删除 | 删除不需要的 Skill |

Skill 内容在识别时会注入 AI 系统提示词的「Skill 层」，覆盖基线中的软偏好。

### 5.5 模型 API 设置

| 配置项 | 说明 |
| --- | --- |
| Mock 模式 | 开启后无需 API Key，返回演示数据或按 Skill 做简单规则抽取 |
| 文本模型 | Base URL、API Key、模型名 — 用于 Excel/CSV/PDF 文本识别 |
| 视觉模型 | Base URL、API Key、模型名 — 用于图片扫描件识别 |
| 连接测试 | 一键测试 API 是否可达 |
| 持久化 | 配置保存到 SQLite，重启后保留 |

默认 Mock 模式为开启，便于首次体验。

## 6. 核心用户流程

### 6.1 首次使用流程

```
打开应用 → 设置中配置模型 API（或保持 Mock 模式）
         → 新建结果表（定义列结构）
         → 可选：在设置中导入/编写 Skill 模板并启用
         → 进入「AI 导入」→ 上传报告 → 核对表格 → 确认导入
```

### 6.2 日常导入流程

```
选择结果表 → AI 导入
           → 上传 CRO 报告（可选选 Skill）
           → AI 自动填入表格
           → 人工修正标红单元格 / 空值
           → 确认导入
```

### 6.3 对话式修正流程

```
上传文件 → AI 首次识别
         → 发现部分列映射不对
         → 在助手对话中说明规则（如「T1/2 取 Summary 页第 3 列」）
         → 点击「立即重导」或发送新消息
         → AI 按新规则重新识别并覆盖表格
         → 确认导入
```

## 7. AI 识别机制

### 7.1 处理流水线

```
用户上传文件
    ↓
文件解析（Excel/CSV/PDF → Markdown 文本；图片 → Base64）
    ↓
组装 System Prompt（基线 + 目标列定义 + Skill + 输出协议）
    ↓
调用 LLM（文本模型 或 视觉模型）
    ↓
解析 JSON 数组 → 结构化行数据
    ↓
填入前端表格 → 用户核对 → 确认导入
```

### 7.2 基线提示词（System Prompt）

内置于后端 `ai_service.py`，核心原则：

| 原则 | 含义 |
| --- | --- |
| 不编造 | 源文件没有的数值填空，不用经验补数 |
| 不扩列 | 只写目标表已定义的 `field` |
| 类型保守 | 数字列只输出可解析数值；select 尽量匹配候选值 |
| 分区勘查 | 优先从「结论/汇总」区取数，方法页/试剂页默认不写 |
| 多实体展开 | 一份报告多行化合物时，拆成多行写入 |
| 对照过滤 | 阳性对照、空白对照默认不导入（Skill 可覆盖） |

完整基线文档见 `doc/AI_data_import/baseline-system-prompt.md`。

### 7.3 两种识别模式

| 模式 | 接口 | 适用场景 |
| --- | --- | --- |
| **一次性识别** | `POST /api/recognize/run` | 文件结构清晰、Skill 已配置，一次出结果 |
| **多轮对话识别** | `POST /api/recognize/chat` | 需要交互式补充规则、反复修正 |

多轮模式下，模型回复分为「短说明 + `<<<ROWS>>>` 后的 JSON 数据」两部分；用户在对话中提出的规则会被记住并在后续识别中生效。

### 7.4 Mock 模式

Mock 模式下的行为：

- 默认返回 6 行演示数据（按列类型生成）
- 若启用了 Skill 且上传了文件，对部分 Skill（如 MMS 人福、HCT116）会尝试从解析正文中做简单规则抽取
- 对话模式模拟 1.5 秒延迟，支持排队与打断交互

## 8. 支持的文件格式

| 格式 | 扩展名 | 解析方式 | AI 通道 |
| --- | --- | --- | --- |
| Excel | `.xlsx` `.xls` `.xlsm` | pandas 读取全部 Sheet，转 Markdown 表格 | 文本模型 |
| CSV / TSV | `.csv` `.tsv` | pandas 读取 | 文本模型 |
| PDF | `.pdf` | pdfplumber 提取文本与表格 | 文本模型 |
| 纯文本 | `.txt` `.md` `.json` | 直接读取 | 文本模型 |
| 图片 | `.png` `.jpg` `.jpeg` `.bmp` `.webp` `.gif` | 保留原始字节 | 视觉模型 |

**限制：**

- 文本类文件解析后截断至约 20,000 字符（防止超出模型上下文）
- 图片在多轮对话的文本模式下仅显示占位说明，完整识别需走视觉模型的一次性识别接口
- 不支持 `.docx`、仪器专有 binary 等格式

## 9. 数据模型与存储

### 9.1 数据库表结构

SQLite 数据库文件位于 `backend/data/data_entry.db`。

| 表名 | 用途 | 主要字段 |
| --- | --- | --- |
| `result_tables` | 结果表元信息 | id, name, description, created_at |
| `columns` | 列配置 | table_id, field, title, type, required, options, description, sort_order |
| `skills` | Skill 模板 | id, name, content, enabled, updated_at |
| `settings` | 模型配置 | key, value（JSON） |

### 9.2 文件存储

| 路径 | 用途 |
| --- | --- |
| `backend/data/uploads/` | 用户上传的源文件（按 UUID 命名） |
| `backend/data/data_entry.db` | SQLite 数据库 |
| `backend/data/skills/` | 历史 Skill Markdown 文件（首次启动时迁移到 SQLite） |

### 9.3 导入结果的去向

当前版本「确认导入」后，数据通过前端事件回调输出（控制台日志），**尚未持久化到业务数据库或化合物库**。这是与完整产品规格之间的主要差距（见第 14 节）。

## 13. 当前边界与已知限制

### 13.1 功能边界

| 项目 | 现状 |
| --- | --- |
| 导入结果持久化 | 确认导入后数据未写入外部系统，仅前端事件输出 |
| 化合物 / 样本关联 | 不支持 SampleResolver、MR-xxxx 匹配 |
| 模板指纹匹配 | 无自动模板匹配引擎；依赖用户手动选择 Skill |
| 双写通道 | 不区分 master（主数据）与 observation（观测） |
| 审计与回滚 | 无 ImportSession、无导入历史、无回滚 |
| ELN 同步 | 不支持 |
| 并发控制 | 无乐观锁、无幂等 hash |
| 权限与多租户 | 无用户登录、无权限体系 |
| 文件大小限制 | 文本截断 20,000 字符；无显式上传体积上限 |

### 13.2 识别质量相关

| 项目 | 说明 |
| --- | --- |
| 依赖 LLM 质量 | 无 Skill 时，映射准确性取决于模型能力与源文件结构 |
| PDF 复杂版式 | 双栏、扫描件、上下标等复杂 PDF 识别率有限 |
| 图片识别 | 需配置视觉模型；Mock 模式下图片不走真实 OCR |
| 无证据回溯 | 当前不支持点击单元格反查到源文件具体 cell/页码 |

### 13.3 交互限制

| 项目 | 说明 |
| --- | --- |
| 确认导入 | 仅做前端校验通过提示，未对接下游写入 |
| 表头变更 | 导入过程中修改表头需关闭重开导入弹窗 |
| Skill 启用 | 全局单选，不支持按结果表绑定不同默认 Skill |

## 14. 与完整产品规格的差距

本产品当前实现对应完整规格文档（`doc/AI_data_import/data-import-agent-spec.md` v0.4.24）中的 **P0 交互原型 + AI 识别引擎** 部分。主要差距如下：

| 完整规格能力 | 当前状态 |
| --- | --- |
| ImportProfile / 库投影（LibraryProjection） | 未实现；用「结果表」替代 |
| 模板匹配引擎（完全匹配 / 部分匹配 / 对不上） | 未实现；用 Skill 手动选择替代 |
| SampleResolver（样本键 → MR-xxxx） | 未实现 |
| 双确认卡（字段映射 + 样本对齐） | 未实现；合并为单表格编辑 |
| ObservationIngress 写入 | 未实现 |
| 多实体报告导入管线（§16） | 部分体现在基线提示词，无独立管线 |
| 导入 Session / 审计 / 回滚 | 未实现 |
| LLM 数据安全策略（strict/standard/open） | 未实现 |
| 错误码体系 | 未实现 |
| 库许可门闸 | 未实现 |

完整规格的分期路线（P0.1 → P0.4 → P1 → P2）可作为后续演进参考。

## 15. 术语表

| 术语 | 含义 |
| --- | --- |
| **结果表** | 用户定义的目标数据结构，包含表名与列配置；对应完整规格中的 LibraryProjection 简化版 |
| **Skill** | Markdown 格式的导入规则模板，描述特定 CRO 版式的映射方式；对应完整规格中的 ImportTemplate 简化版 |
| **基线提示词** | 内置的系统级 AI 指令，教模型如何勘查和保守映射 |
| **Mock 模式** | 无需真实 API Key 的演示模式，返回模拟数据 |
| **AI 导入** | 上传源文件后由 AI 自动识别并填入结果表的过程 |
| **确认导入** | 用户在表格中核对数据后点击确认；当前仅做校验，未写入下游系统 |
| **CRO** | Contract Research Organization，合同研究组织，如药明、人福、3D BioOptima、普瑞昇等 |
| **库配导入** | 完整产品规格中的正式产品名：与化合物库同售的数据导入功能 |
